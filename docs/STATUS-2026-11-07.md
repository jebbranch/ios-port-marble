## 3. 音频（主战场）

### 3.1 一句话结论

**含 `PCM_DEC 0x40bf` + `PCM_CNV 0x40c0` 的 856 B A 形式图能开、能起、能推完 120 帧，
DSP 回了 121 个 `DATA_BUFFER_DONE_V2`，`timeout=0` —— 扬声器不响。用户三次都没听到。**
（−6.0 dBFS、约 0.7 s、120×6 ms。）

也就是说：**控制面、图内容、数据面、ACK 全部绿灯，唯独不出声。** 现在做的是把「无声」
**定性到一侧**（AP 侧协议/资产 vs 硬件侧 TDM/AFE/功放）。

### 3.2 已经钉住的事实（都有 ring 做证）

- `SHM_MAP` 地址高字是 **stream index（`msw=1`）**，不是 33 位地址；改对之后不再挂总线。
- **`DATA_BUFFER_DONE_V2` 只是一张收据**：step=1 时 1–2 ms 回一个，而一帧是 6 ms 音频
  （厂商 20.5 ms/4096 B ≈ 实时）。它的 8 个字里**结构上没有任何"消费"字段**
  ⇒ 历史上的 `not consumed=0` 证明的只是"入队被确认"。
- `GRAPH_OPEN` 有两种正文**形式**：
  - **A 形式** = 平铺 `{iid=1, param, size, err}` 记录（16 B 头、8 对齐）——
    **我们唯一被接受过的形式**；
  - **B 形式** = `{total, count}` 的 ACF 图索引 —— 把它当 APM 头读，前 16 字给出
    `param_size = 0xB0000002`（**2.75 GiB**）。它是 **GSL/ACDB 侧结构，从来不是 APM 的
    wire payload**。五次 B 形式发送**全部把 APM 打死**（之后连探活都没回应）。B 形式路线关闭。
- 当代图 key 集合 = `{0xb0000002, 0xb0000025, 0xb0000024, 0xb0000023}`（slack 0），
  上一代才是 `0xb0000081` ⇒ `g_graph_vendor4`(2724 B) 是**上一代且自身索引超界 4 B**，
  由它得出的一切"内容被拒"结论**作废**。
- 那五枪旧 2960 用了代码默认 `off=16 / len=2944`，**削掉了 entry[0] 的头** ⇒
  它们的 `status=0x2` 是自伤，不是判决。
- 被接受的 760 B 正文里**同时有 WR `0x40bd` 和硬件段** —— 我两次"缺模块"的说法都被
  逐字 dump 推翻过。缺口只有 `PCM_DEC 0x40bf` + `PCM_CNV 0x40c0` + 它们的 port + 一次 rewire。
- 厂商 11-05 抓包（含接收方向）复核：`GRAPH_OPEN` 是**三次带外调用**
  （src `0x2010`/496、`0x2011`/2872→2904、`0x2012`/2032），共用一个 `0xb0d89128` handle，
  和 `DATA_BUFFER` 共享；那条 18504 B 的 APM `SET_CFG` 用它**自己**的 handle `0xb0d92ac8`；
  每一句在 RX 里都有 `status=0` 的回答。
- 我们**从未发过**的一条命令族：`0x0100100e REGISTER_MODULE_EVENTS`
  （body `{iid, 0x0800103f, 1}`）⇒ 第 54 枪补发过，`status=0`，仍无声 ⇒ **该族排除**。
- `g_apm_cmd` → `g_apm_xfer`（`sweet_glink.c:2788-2802`）等待 **5000 ms**；
  `sweetrspwait`（`:6598-6612`）**只管数据面的单缓冲探针**。⇒ "EOS 无应答是因为窗只有 100 ms"
  **已撤回**，那个按住的第 63 枪从没开过。
- 收包路径（`:798-818`）按 local channel id 重组并置 `g_rsp_ready`，**不按 opcode/token 过滤**。
- **`EOS_RENDERED` 从未到达**（第 64 枪）：`0287` 的全量收包日志被证明**可用**
  —— 同一 ring 里 137 条、opcode 分布正常（121 个 DONE、9 个 basic result、5 个 PRM done、
  1 个 SPF state、1 个 MEM_MAP_DONE），而我们发出 EOS 之后**一条都没收到**。
  ⇒ 这个零是**关于对端的正面结论**，不是仪器坏、不是窗短、不是丢弃：
  四因（分支没跑 / 窗太短 / 收包丢弃 / 对端不发）逐一排除完毕。

### 3.3 已排除的轴（每一轴都花了真实代价，别再回来）

正文尺寸（2960→1536→1024→760 全 wedge，而我们 760 B 平正文每枪都答 ⇒ **不是尺寸，是形式**）·
传输方式 / handle / 区内偏移 / token · src 端口（`0x2011` 开过两次都 `status=0`）·
幅度 / 时长 / 节律（`sweetvol` 家族到钳位上限 −0.27 dBFS、`sweetbufs` 到 watchdog 120）·
TDM 位时钟票位置（早/晚两种顺序都跑过，120 个 buffer 流过仍无声）·
WR 媒体格式 · MFC 输出格式（四个相位读回都有效）· `REGISTER_MODULE_EVENTS` ·
图的代次与 key 集合 · 转换级模块内容（PCM_DEC+PCM_CNV 加进去以后 = 三条有效负读数）·
EOS 事件等待窗 · 动态通道吞包 · 收包仪器本身 · 时钟投票体（`0x204@12288000/attr4` 逐字节确认）·
`iid` 当边界 · AP 侧 SPMI 直读功放（bit-bang 相位之后才失去地址性，是**仪器行**不是功放判决）。

### 3.4 当前未决

`EOS_RENDERED` 收不到之后，只剩两种解释，而**它们分在两侧**：

1. **固件侧/资产侧**：这颗固件不为我们这个端点/策略发这个事件，或者事件发往**我们没开的通道**；
2. **硬件侧**：APM 一路都答得好好的，但 TDM 接口 / 时钟 / 数据线、AFE 端口配置、
   AW882xx 的 power/reset/mute 里有一头没通 —— 图"跑起来了"但没有任何东西到达扬声器。

AP 侧的 EOS/事件仪器路线**已按止损条款关闭**（第 64 枪）。B 线的做法是：先用**一枪零资产依赖**
的实验把外部评审的 AFE-id 疑点判掉（B1），再决定要不要投三图三端口重建（B3）。

## 5. GPU（冻结中，别自己动）

- 读数层面：AP 能读写全部 GPU 寄存器、GMU 固件能装进 TCM；卡点是 **CX 域电源无法真正打通**。
- 历史上"一放复位机器就停"那条结论**已撤回**（`delay()` 会阻塞、G4 跳过了 SPI mask、
  0228 数的是串扰）。冻结不是因为"危险动作"，是因为 **reopen 门还没满足**：
  需要一条真正的 spin heartbeat + 一条能活过 stall 的输出通道。
- **绝对红线：不要建议主动 collapse GPU** —— 那样永远回不来。**没有用户明确点头，不开任何 GPU 枪。**
- 外部 PR #1 的重放已证明干净（`applied=212`，没有跳过），但合并被音频轮**挤到队列后面**：
  它会**在取产物的中途覆盖 kernel-latest**。它的两笔债必须**重编号到 0289+**（现在补丁链已经到 0288），
  并把 CNTVCT spin 界住。task #37。

## 6. 震动（内核侧完成，剩用户态半条）

- AP 侧 SPMI 直接驱动**真的能振**（44/44 下都感觉到）⇒ **输出这一侧已解决**。

## 9. 构建 / CI / 复现（新会话最可能先用到）

  `SWEET AUDIO: build v`。摘要不一致就失败，除非 `ALLOW_DIGEST_MISMATCH=1` 且 `EXPECT_MARKER` 已命中。

- 补丁链：`work/chain-tree` 是链的 HEAD（顶端 **0288**），`work/xnu-gh/xnu/patches/**` 是产物；
