把 iOS 16 的内核，
开机到一台
Redmi Note 12 Turbo

Apple 开源的 XNU（iOS 16 那一代）跑在小米这颗 Snapdragon 7+ Gen 2 上，上面是 iPhone X 的 iOS 16.7.16 用户态：launchd、系统守护进程、backboardd、SpringBoard、自带 App。引导链是自己写的裸机 shim，从 fastboot 直接把镜像推进内存跑，不刷 boot、不写 userdata、不动分区表。

它是研究项目，不是一台能用的手机。现在能进主屏幕、能触摸、能用硬件按键；音频暂停在 73/120，Wi-Fi 正在施工，GPU 第二优先。缺的东西比列出来的多。

01 / 启动链

四段路，没有一段是现成的

从 fastboot 到主屏幕之间原本什么都没有：没有 UEFI，没有 Linux，没有厂商驱动。每一段要么自己写，要么把 iPhone 的驱动搬到一颗它从没见过的高通 SoC 上。

  1. ABL

    小米的 fastboot

    boot.img header v4（header 1584 / signature 4096）。只借它把镜像送进内存；verifiedbootstate 是 orange。

  2. shim

    自写 AArch64 裸机

    读硬件事实、配 MMU 与 16 KB 页表、把 splash 画进 framebuffer、组装 XNU payload，然后跳进内核。

  3. XNU

    xnu-8796.141.3，SWEET / DEVELOPMENT

    GICv3、VTIMER INTID 27、8 核 SMP。设备树由 D22AP 的 .adt 加上从真机 live FDT 采集的 marble 地址合成。

  4. userland

    iPhone X 的 iOS 16.7.16

    根文件系统是 userdata 尾部切出来的 HFS+ 分区；launchd、SpringBoard、自带 App 原封不动。

搬驱动时要付的三笔学费

msr CNTP_CTL_EL0 → NOP
这颗 SoC 在 EL1 不给物理定时器，XNU 只能走 CNTV。不改就直接 Undefined kernel instruction。
GICR stride 是 0x40000，不是默认的 0x20000
marble 的 redistributor 间距 256 KB。用 cpus=1 时永远只碰 offset 0，所以这个差异一直藏着；要起 8 核就必须显式传 gicrstride=0x40000。
UFS 要往设备 W-LUN 0xD0 发 START STOP UNIT
ABL 交接时 UFS 是掉电的，普通 LUN 的唤醒无效。cdb[4]=0x10 之后 INQ / TUR / CAP / READ / GPT 才全部成立。

03 / 时间轴

十五个节点，从一句「不可能」到 2026-11-28

日期取自仓库提交时间戳与 GitHub Actions 的构建记录，顺序按实际发生排；docs/status-log.md 里若干条日期在几次转手之后已经和当时不符，不作依据。

  1. 2026-10-21 15:58

    「红米 Note 12 能刷 iOS 吗？」

    得到的回答是：不可能。iOS 不开源、Secure Boot、SHSH 签名、Secure Enclave，只认 A 系列芯片。项目是从这句「不可能」开始的。

  2. 2026-10-21

    shim 探硬件，最小根在内存里

    16 KB 页、MIDR、GICv3、framebuffer 全部实测通过。19:05 第一次 shim 上机是乱码 + 红蓝屏，19:09 修复版拍到 P1 诊断；19:31 CI run #1 成功。23:00 panic 在 msr CNTP_CTL_EL0，NOP 之后 XNU 到 console；23:19 屏幕打出 userland alive——16 MB HFS+ 最小根由 shim 以 rd=md0 带进内存，里面只有一个静态 /sbin/launchd，不碰 UFS。

  3. 2026-10-22

    UFS 醒过来

    ABL 交接时 UFS 是掉电的，普通 LUN 的唤醒无效；向设备 W-LUN 0xD0 发 START STOP UNIT（cdb[4]=0x10）之后 INQ / TUR / CAP / READ / GPT 全部成功，读出 SAMSUNG KLUEG8UHGC-B0E1、4 KiB 块、约 256 GB。22:53 文件级备份校验完成；深夜开始把约 11 GiB 的 HFS+ 镜像按 1 GiB × 16 块写进 userdata 尾部，GPT 全程没动。同一天发现 0082 的 hunk 行号写错导致 CI 静默跳过补丁——marker 门由此而来。

  4. 2026-10-23 01:05

    Apple logo + 进度条：iOS 在引导

    launchd_cache_loader 过了，launchd 已经在跑用户态引导，不再是内核 panic 屏。02:07 日志确认 SpringBoard(pid 26) 与 backboardd(57) 都在运行、framebuffer 交换 19.4 万次；停在进度条的原因是缺 preboot 卷、独立数据卷、SEP、前台会话、GPU 加速和基带/蓝牙守护进程。

  5. 2026-10-23 10:21 → 15:11

    进 Setup，再进桌面

    10:21「成了，进 setup 了」：绕过 datamigrator + 激活种子这条路走对，随后开始新写 Goodix GT9916R over SPI 的触摸驱动。15:11「进桌面了，但是没有壁纸，锁屏时钟是红色的」：SetupDone 生效，用户态彻底过了 Setup；壁纸与红色时钟归到 WallpaperKit / 颜色管线，还没有 GPU 合成。

  6. 2026-10-23 → 24

    音频开工

    LPASS/WCD938x 只读探针 → AOP command DB → 走 TZ PAS 装载与释放 ADSP → 最小 GLINK/GPR 客户端 → 通过 q6prm 投 LPASS。第二天打开厂商自己的 AudioReach 播放图、灌 1 kHz、开始碰功放 I2C，也第一次试了 HAP520 震动引擎。

  7. 2026-10-27

    八核是修音频时顺手修的

    marble 的 GICR 间距是 0x40000 而不是 XNU 默认的 0x20000；改成运行时可配、ADT 里放八个核，8/8 起来。同一天记下 apps-smmu 的死路、盘了 GPU 可行性（kgsl-smmu 与 apps-smmu 是两颗独立 SMMU），并确认喇叭走 TERTIARY TDM + 两颗 AW882xx，不是 WSA。

  8. 2026-10-30

    震动：输出侧解决

    AP 侧 SPMI 直驱 PMIC HAP520，44/44 次有震感、震感与设置一致。同一轮修掉 SpringBoard 的 TCC 崩溃（补 16 个 usage 键）。剩下的不在硬件：UIKit / CoreHaptics 的请求被 backboardd 的用户态 gate 拦下，这条线当天暂停。

  9. 2026-11-02

    音频数据面打通

    门槛不是厂商那 18 KB 校准，而是 S1 叶子页表项的 AP 位——DSP 非特权读被 SMMU 终止。改到 sweets1ap=3 之后 DATA_BUFFER done status=0 回来，1200 个 buffer 跑完并正常复位。

  10. 2026-11-03

    mediaserverd 来 open 我们的壳

    线上格式在本机 libar-gsl.so 上逐条反汇编复验：记录头 16 B、OOB 包结构、正文 ≤256 走带内；SHM 映射的高 32 位是 stream index 而不是地址。pid 28 调了 method_Open。

  11. 2026-11-05

    一条轴关门，两条线改道

    带外 SET_CFG 的 E–N 十轮把地址、传输、长度、正文字节逐格排除；N1 的哨兵证明之前那些 err=0 其实是「没人写过」。同一天 Wi-Fi 决定暂缓，基带开线先做零开机普查。

  12. 2026-11-07

    图的内容判死，GPU 冻结

    离线核清图生成轴（2960 是当代四个 key，旧的 2724 属于上一代且自身索引越界）；逐字 dump 两次推翻「图里缺 DEC/CNV」，真正缺的是 PCM_DEC + PCM_CNV。856 B 的图能开、能起、能推 120 帧，人耳三次都没听到；EOS_RENDERED 在收包仪器被证明活着的前提下从未到达。GPU 线转冻结。

  13. 2026-11-08 → 13

    修功放，然后接上 HAL

    功放两处真实缺陷实机生效：初始化不再执行诊断复位，寄存器写合成三字节单消息，两颗的表值 b440 / 05a9 读回一致。11-10 重开音频做 capture-only HAL；第 70 轮 HAL → AudioReach 连续流 30/30/30、六条控制应答全 0——仍然不是出声。

  14. 2026-11-14 → 15

    定位到功放没有 TDM 时钟

    第 72 轮有效无声：两颗 AW88266 的 profile / ID / vol 都对，清掉 PWDN 之后 SYSST=0、PLL 全 0，安全门在任何 period 提交前拒绝并双关断。0297 补上厂商那张精确 PRM 票，第 73 轮判为 PRM 回包解析失配——应答是 0x02001002 配 0x0800102c，不是 BASIC_RSP；0298 已离线把绑定修好。声音仍未证明。

  15. 2026-11-20 → 28

    Wi-Fi 成为主线，GPU 转为第二优先

    引入 FoXLinne 的 marble 参考。第 74 轮只读 handoff 通过，确认 QCA6490/PCIe0 交接后保持关闭；端点识别尚未验证。0302/0303 把 109 个无线栈对象、固件、DMA/SMMU 核心离线接进同一个对象，但还没进入 XNU 的实际启动路径。预算仍 74/120。

04 / 踩过的坑

一个人踩不完所有的坑，所以坑要写下来

这个项目最贵的资源不是时间，是开机次数——一次开机等于一次真机、一次取日志、一次归因。下面四条机制都是为了把它变便宜才长出来的。

marker 门：让被跳过的补丁表现为一次 CI 红

每个补丁自带一条唯一的 printf 字面量，GitHub Actions 构建完 XNU 后在产物里逐条 grep。补丁因为基线选错而没打上时，红的是 CI，不是一次白花掉的开机。改一条字符串必须在同一个 push 里删掉旧 marker。

cmdline 只有 590 字节

启动参数塞到 607 字节会被截断，而且是静默切值：sweetbufs=30 变成 sweetbufs=3，于是你拿一个约 12 ms 的音当负读数写进结论。现在 mkimage.sh 在超长时直接报错退出，不许绕过。

日志要从磁盘尾取，而且先对身份

内核 console 在 exec bluetoothd 之后基本是哑的，所以关键行直写 ring buffer，落在 userdata 尾部，复位后用脚本拉回来。单条记录约 240 字节、截断不加分隔符，一个“长行”其实是几条粘在一起。每轮先 grep sweettime 对身份——对不上意味着这一轮根本没写 ring，而脚本会安静地把上一轮给你。

判据表必须在开机之前 commit

一次实验只动一个语义变量，并打印它实际用的参数；判决表在开机之前写死，事后不改。仪器必须能自证失败：只在已被证明会执行的路径上打印，否则明确标注“非判据”。尺寸凑对了不算证据——同一个 u32=18504 在厂商 ACDB 里能出现几十次。

05 / 还差什么

没做到的部分，才是这份清单的意义

声音。音频暂停在 73/120。数据面、HAL 连续流、功放修复都已通过；最后一次有效负读数是功放没有 TDM 时钟。0298 已离线修好 PRM 回包绑定，尚无新内核/镜像/开机。

Wi-Fi。第 74 轮只读 handoff 通过，确认 QCA6490/PCIe0 交接后保持关闭；端点识别尚未验证。0302/0303 已离线集成 109 个无线栈对象、固件与 DMA/SMMU 核心，但还没进入 XNU 的实际启动路径。

图形。每个像素仍是 CPU 算的。FoXLinne 的上游 iOS 18 GPU 实现可参考，但 iOS 16 适配尚未开始；旧 XNU 8796 线仍冻结。

存储。root 镜像位于 userdata 尾部，但 f2fs 没有缩小、GPT 没有改。研究机日常还要开 Android，写满就会覆盖 root；目前只能开机前重读卷头签名与 free 块数，发现被覆盖就重新分块写尾部。

可用性。缺 preboot 卷、独立数据卷、SEP、前台会话；部分 App 看门狗超时；空密码仍要求输入（用户态 bug）。这套东西的目标不是日常手机，而是回答「Apple 的内核离开工厂校准的硬件能走多远」。

已证伪的路线。SMMU 死路、拿 DATA_BUFFER 当探针、用 tinyplay 扰动测时钟——每一条都花过真机开机，列出来是为了省下你的。

06 / 怎么跑一遍

你需要自备的文件

仓库是纯代码、补丁与文档，不含任何 Apple、高通或小米的二进制。XNU 源码由 CI 从公开源构建；下面三样只能从你自己的设备来。

需要自备的文件
文件来源
d22ap.adt你自己的 iPhone X（D22AP）iOS 16.7.16 IPSW。Apple 版权内容，不可再分发。
adsp2.mdt 与分段你自己手机上的 /vendor/firmware/，用 extract_adsp_fw.sh 抽取（需要 root）。
HFS+ 用户态镜像你自己的 iPhone X IPSW 或设备。仓库不提供，也不提供获取渠道。

构建 → 启动 → 取日志，全程只 fastboot boot

# 1. 取回 CI 产物并打上 CNTP_CTL NOP（一定要用处理过的内核）
GH_REPO=<你>/ios-port-marble ./scripts/fetch_kernel.sh

# 2. 从手机抽 ADSP 固件
SERIAL=<你的机器> ./scripts/extract_adsp_fw.sh

# 3. 生成 RAM-only 启动镜像
D22AP_ADT=/path/to/d22ap.adt ADSP_FW_DIR=$PWD/adsp-fw ./scripts/mkimage.sh

# 4. 启动。不写任何分区。
SERIAL=<你的机器> ./scripts/boot_ram.sh images/shim-iosroot-adsp.img

# 5. 取回这一轮的 ring 日志
SERIAL=<你的机器> ./scripts/pull_logs.sh run1

只对你自己的设备使用。测试前一定先备份原机数据——别学我不备份就在线调整 userdata 分区大小，这很吃运气。另外要知道怎么进 fastboot（Power + Vol Down）和恢复路径。内核 panic 时屏幕会花，推荐先拍照，再记下 pc / lr / far 然后重启。

07 / 参与

欢迎一起来折腾

  • 有同款机器（Redmi Note 12 Turbo / marble / SM7475）：帮忙实机复现、抓日志、读寄存器、验证补丁。
  • 做过 XNU / IOKit / 驱动移植：补丁和代码评审都欢迎，一个 PR 尽量只做一件事。
  • 懂高通 PMIC / RPMh / SMMU / AudioReach：如果文档里有错，或者这条路你早走通过、走死过，请一定告诉我们。

开 Issue 请贴四样：现象、logs/ring-*.txt、启动参数、以及镜像标识 sweettime。有这四样，同一轮实验就能复现。范围不限于 bug——“这条路我试过，结论是 X”同样有价值。

失败的尝试也请顺手写进 docs/，下一个人就不会重走。

Issues and pull requests in English are welcome too.

站在谁的肩膀上
